# Technical Legal-Risk Review — Approx AI 1.0.0

> **This is a technical legal-risk review, not legal advice.** It flags items a qualified lawyer
> should confirm before commercial launch (in particular for Pakistan, the EU/UK and app stores).

| Area | Item | Risk | Notes / action |
|---|---|---|---|
| Model license | `Qwen/Qwen2.5-3B-Instruct` (base for Nick 4.8) | MEDIUM | Distributed under the Qwen license on its model card (the 3B variant has historically used the *Qwen Research* license, which restricts commercial use). **Verify the current license on the model card before commercial use**; if commercial use is restricted, obtain permission or switch to an Apache-2.0 Qwen2.5 size (e.g. 7B) or another permissively licensed base. Attribution and naming requirements may apply to derivatives. |
| Model naming | "Nick / Hike / Sona / FAB" | LOW | Product names for Approx models. Do not market Nick as "Qwen"; disclose the base model where the license requires. Only Nick has a training pipeline; Hike/Sona/FAB require their own licensed backends — do not claim capabilities they don't have. |
| Dataset licenses | Seed set | LOW | Original Approx-authored content (45 records). |
| | Candidate public datasets (OASST1, Dolly-15k, GSM8K, Aya, Kaggle sets) | MEDIUM | None were downloaded (hosts unreachable). Each is `approved:false` until its license is verified at source. Dolly-15k is CC BY-SA 3.0 (share-alike may attach to derived datasets); Kaggle datasets carry per-dataset licenses — some are non-commercial. Provenance manifest records license per source. |
| User data for training | Consented history | MEDIUM | Opt-in (off by default), per-chat eligibility, withdrawal supported, PII scrubbing, FAB excluded, no user IDs in datasets. Needs a clear privacy policy + terms describing this use, lawful basis (consent), and a process to remove a user's data from *future* datasets after withdrawal (already-trained weights cannot "unlearn" — disclose this). |
| Privacy / data protection | Pakistan PECA 2016 & draft Personal Data Protection Bill; GDPR/UK GDPR if serving EU/UK users | MEDIUM | Implemented: data export, deletion, consent records (audit log), memory controls, minimal collection. Still needed: privacy policy, terms of service, data-processing records, retention schedule (audit/security logs are retained indefinitely now), DPA with hosting/mail/inference vendors, breach-notification procedure. |
| Data retention | Chats in trash, audit logs, mail outbox | LOW | Define and implement retention periods (e.g. trash purge after 30 days; outbox purge after 7 days). |
| Copyright | Model outputs; uploaded content; research fetching | LOW–MEDIUM | Users upload content they must have rights to (terms). Research fetches pages at user request and quotes excerpts with citations — keep excerpts short, respect robots/site terms; don't store fetched pages beyond the request (current behaviour). |
| Trademarks | "Approx", "Approx AI", "Approx Technology", logo | LOW | Clear trademark availability in target markets. The product does not use Anthropic/Claude branding. "Claude-class UX" is a design goal only; no Anthropic code, assets or APIs are used. |
| Third-party packages | Backend/web: none. Android: platform only. Training: PyTorch (BSD), Transformers (Apache-2.0), PEFT (Apache-2.0), bitsandbytes (MIT), Accelerate (Apache-2.0), Datasets (Apache-2.0), vLLM (Apache-2.0) | LOW | Include NOTICE/attribution files when redistributing. |
| Build tooling | Android `android.jar` (API 33) obtained from a public GitHub mirror (`Sable/android-platforms`) because Google's SDK host was blocked | LOW | Compile-time stub only (not shipped in the APK). For production builds use the official Android SDK under its license terms. |
| APIs / connectors | No third-party connectors shipped | INFO | When adding Google/GitHub connectors, comply with each platform's API terms and OAuth verification. |
| Security features | FAB defensive-security tooling | MEDIUM | Restricted to authorized/defensive use by policy, superadmin grants (audit-logged) and a refusal filter. Terms should prohibit unauthorized testing; keep grant records (reason is mandatory). Dual-use export-control review recommended if offering advanced security tooling internationally. |
| App stores | Google Play | MEDIUM | targetSdk 33 — Google Play currently requires a newer targetSdk for new apps/updates; rebuild with the latest SDK before Play submission. Needs a privacy policy URL, Data Safety form, account-deletion link (implemented in-app). AI-generated content policies apply (report/flag mechanism recommended). |
| Payments | Subscriptions | INFO | No payment processing in 1.0 (admin-assigned plans). Adding paid plans requires a payment provider and, on Android, Play Billing for digital goods. |
| Consumer disclosure | AI output accuracy | LOW | UI shows "Approx AI can make mistakes — verify important info." Religious, medical, legal and financial answers should recommend qualified professionals (seed data does this for religious rulings). |
